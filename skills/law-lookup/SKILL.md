# 법령 조회

길이 둘이다. **서류에 적는 조문은 반드시 ①로 확인한다.**

| | ① 현행 조회 | ② 내려받은 저장소 |
|---|---|---|
| 무엇 | 법제처 Open API를 감싼 [korean-law-mcp](https://github.com/chrisryugj/korean-law-mcp) 공개 서버 | [law-go-kr-obsidian](https://github.com/moomoogrange/law-go-kr-obsidian) 사본 (법령 3,037건) |
| 최신 여부 | **조회하는 날의 현행 조문.** 과거 날짜 기준 조회도 된다 | 저장소를 만든 날의 사본. 그 뒤 개정은 없다 |
| 조 번호 | 가지번호까지 정확 (제18조의3) | 가지번호가 빠져 있다 (제18조로만 적힘) |
| 있는 것 | 법률·시행령·시행규칙, **별표·서식**, 행정규칙(고시·훈령), **조례**, 판례·해석례 | 법률·시행령·시행규칙 본문 |
| 좋은 점 | 정확하고 최신 | 빠르다. 전체 본문 검색, 법령 사이 링크 따라가기, 인터넷 없이 조회 |
| 쓰는 때 | 인용, 기한·숫자 확인, 서식 찾기, 제출 전 대조 | 어느 법에 무엇이 있는지 찾기, 여러 법령 훑어보기 |

**순서**: ②로 넓게 찾고 → ①로 현행 조문을 확인해 인용한다. 둘이 다르면 ①이 맞다.

## ① 현행 조회

세션에 `korean-law` MCP 도구(`search_law`, `get_law_text`, `get_annexes`, `search_decisions` 등)가 붙어 있으면 그것을 쓴다. 이 플러그인을 설치하면 함께 연결된다. 도구가 없거나 하위 에이전트라서 못 쓰면 스크립트로 같은 서버를 부른다.

```bash
law.py live search 비영리법인 설립                 # 현행 법령 찾기 — 이름, MST, 공포일, 시행일
law.py live art 민법 제32조                        # 현행 조문
law.py live art "법인세법 시행규칙" 제18조의3        # 가지번호 그대로
law.py live art 법인세법 제24조 20240101            # 그날 시행 중이던 조문
law.py live annex "법인세법 시행규칙" 63의5          # 별표·서식
law.py live tools                                  # 쓸 수 있는 도구 목록
law.py live call search_decisions '{"domain":"interpretation","query":"비영리법인 주무관청"}'   # 해석례·판례
```

- 인증키 없이 공용 한도로 동작한다. 자주 쓰면 [법제처 Open API](https://open.law.go.kr)에서 무료 인증키(OC)를 받아 플러그인 설정에 넣거나 `LAW_OC` 환경변수로 준다.
- 조회 내용은 공개 서버(mcp.gomdori.app)를 거쳐 법제처로 간다. 법령 이름과 조 번호만 보낸다. **신청인의 이름·주소 같은 개인정보를 조회어에 넣지 않는다.**
- 결과에 `[NOT_FOUND]`가 나오거나 서버에 닿지 못하면 지어내지 않는다. ②로 읽고 "현행 확인 못 함"이라고 적는다.
- 법령 이름이 바뀐 경우(부처 개편 등) 서버가 옛 이름과 새 이름을 함께 알려 준다. 서류에는 새 이름을 쓴다.

## ② 내려받은 저장소

이 스킬 폴더의 `scripts/law.py`를 쓴다. 파이썬 3과 git만 있으면 된다.

```bash
law.py setup                               # 처음 한 번 내려받기 (update 도 같다)
law.py where                               # 위치와 마지막 갱신일
law.py find 성평등가족부 비영리법인          # 법령 이름 찾기 (낱말을 모두 포함)
law.py meta 법인세법                        # 파일 목록, 공포일, 시행일, law.go.kr 주소
law.py toc 민법                             # 조문 제목 목록
law.py art 민법 32                          # 조문 본문 (기본은 법률)
law.py art 법인세법 39 시행령                # 시행령·시행규칙은 파일 이름을 뒤에 붙인다
law.py art 법인세법 공익법인등의범위 시행규칙  # 번호 대신 조문 제목 낱말로도 찾는다
law.py grep "설립허가" 행정권한의위임및위탁에관한규정   # 본문 검색 (법령명을 빼면 전체)
```

- 내려받는 곳은 `~/.local/share/baruch/law-go-kr-obsidian`. 다른 곳의 사본을 쓰려면 `BARUCH_LAW_DIR`로 가리킨다.
- 내려받은 지 7일이 지나면 조회할 때 스스로 최신 사본으로 맞춘다.
- 법령 이름은 띄어쓰기 없이 적어도 되고 일부만 적어도 된다.
- 저장소 폴더를 Read·Grep 도구로 직접 읽어도 된다. 위키링크 `[[법령/민법/법률|민법]]`은 그 법령 파일의 경로다.

## 반드시 지킬 것

0. **파일을 고른다.** 저장소 조회에서 파일을 적지 않으면 법률 → 대통령령·시행령 → 부령·시행규칙 순으로 하나를 읽는다. 직제처럼 법률이 없는 법령은 대통령령이 먼저 나온다. 다른 파일은 이름을 뒤에 붙인다. 저장소 조문의 시행일이 저장소 갱신일보다 뒤일 수 있다(공포는 됐고 시행이 나중인 조문). 그대로 적는다.
1. **인용하는 조문은 현행 조회로 확인한다.** 법령명, 조 번호(가지번호 포함), 조문 제목, 시행일을 적는다. 현행 조회를 못 했으면 "저장소 사본(갱신일 ○○) 기준, 현행 확인 못 함"이라고 밝힌다.
2. **저장소로만 읽은 조문은 번호를 단정하지 않는다.** 가지번호가 빠져 있어 같은 번호의 조문이 여럿 나온다. 조문 제목으로 고르고, 번호는 현행 조회로 확정한다.
3. **과거 일은 그날의 조문으로 본다.** 이미 지난 신청·처분·납부를 따질 때는 `live art … 날짜`로 그날 시행 중이던 조문을 읽는다.
4. **없는 것은 없다고 한다.** 관청 내부 지침과 처리 관행은 어디에도 없다. 찾지 못한 조문은 `[조문 미확인]`으로 표시한다.
5. **읽은 만큼만 말한다.** 조문 본문을 읽지 않고 번호나 내용을 말하지 않는다.
