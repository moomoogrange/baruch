# 상호 검토

서류는 세 사람이 본다. 쓴 사람은 자기 글의 틀린 곳을 잘 못 본다.

| 누가 | 무엇을 보나 | 고치나 |
|---|---|---|
| 바룩 (baruch) | 쓴다. 지적을 받아 고친다 | 고친다 |
| 사반 (shaphan) | 원문 대조 — 조문, 사실, 서류 사이, 셈, 기재사항 | 고치지 않는다 |
| 나단 (nathan) | 받는 쪽 입장 — 보완·반려·불허가·지정 거부가 나올 곳 | 고치지 않는다 |

## 언제

다음 때에는 **빠짐없이** 거친다. 신청인이 서두르라고 해도 건너뛰지 않는다.

1. 설립허가 신청 서류 묶음을 다 쓰고 사전 보완 점검(`06-예상-질문과-답변`, `17-보충-설명서`)을 했을 때
2. 국민신문고에 낼 글과 첨부 목록을 만들었을 때
3. 설립등기 준비표를 만들었을 때
4. 공익법인 지정 추천 신청 서류를 만들었을 때
5. 보완 요구를 받고 서류를 고쳤을 때
6. 신청인이 날인·서명·제출하기 직전
7. 관청·법원·등기소에 내는 그 밖의 모든 서류 (`work-engine` 6단계)

## 순서

1. **묶는다.** 검토할 파일 목록, 단계(주무관청·등기소·세무서), 기초사실 파일, 주무관청과 그 규칙 이름을 정리한다.
2. **두 검토자를 함께 부른다.** 한 번에 둘을 부르되 서로의 결과를 보여 주지 않는다. 두 눈이 독립적이어야 한다.
   - 사반에게: 파일 목록, 기초사실 파일, 대조표 위치. "작성자의 설명 없이 파일만 보고 대조하라."
   - 나단에게: 파일 목록, 단계, 주무관청 규칙 이름, 관청이 준 지침·회신. "받는 쪽 자리에서 읽어라. 담당자가 물을 질문과 보완을 요구할 서류를 빠짐없이 내라."
   - 작성자의 결론이나 "문제없다"는 말을 넘기지 않는다. 파일과 사실만 넘긴다.
3. **결과를 적는다.** 돌아온 보고를 `법인설립/검토/사반-날짜.md`, `법인설립/검토/나단-날짜.md`에 그대로 쓴다. 줄이거나 다듬지 않는다.
4. **고친다.** "막음"과 "고침·보강" 지적을 바룩이 하나씩 고친다. 지적마다 고쳤는지, 고치지 않았다면 왜인지를 `법인설립/검토/처리-날짜.md`에 표로 남긴다. 검토자 말이 틀렸다고 보면 고치지 않고 근거를 적는다.
5. **다시 본다.** 고친 뒤 같은 두 검토자를 다시 부른다. **"막음"이 0이 될 때까지** 되풀이한다. 세 번을 돌아도 막음이 남으면 멈추고 신청인에게 남은 문제를 그대로 알린다.
6. **신청인에게 보고한다.** 아래를 짧게 알린다.
   - 사반 판정, 나단 판정, 몇 번 돌았는지
   - 고친 것 가운데 중요한 것
   - 고치지 못하고 남은 것: 신청인이 채울 사실, 관청에 물을 것, 전문가 확인이 필요한 것
   - 검토자들이 확인하지 못한 것

## 지킬 것

- 검토자가 서류를 직접 고치게 하지 않는다. 고친 사람이 다시 검사하는 꼴이 된다.
- 검토 결과가 "통과"여도 **허가·등기·지정을 보장하지 않는다**고 신청인에게 말한다. 판단은 관청이 한다.
- 두 검토자의 말이 서로 다르면 둘 다 신청인에게 보여 준다. 한쪽을 골라 숨기지 않는다.
- 하위 에이전트를 부를 수 없는 환경이면, 같은 순서로 직접 검토하되 "독립 검토가 아니라 자체 검토였다"고 신청인에게 밝힌다.
