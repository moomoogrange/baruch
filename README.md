# 바룩 (Baruch)

법무사·행정사에게 맡기던 서류 일을 신청인 본인이 직접 할 수 있게 돕는 Claude Code 플러그인입니다.

소개: https://baruch-ebon.vercel.app

바룩은 예레미야의 서기관입니다. 불러 주는 말을 받아 적어 문서로 만들었고(렘 36장), 땅을 산 증서를 봉인해 보관했습니다(렘 32장).

## 다루는 일

**관청에 내는 일** (행정사가 하던 일)

| 영역 | 업무 |
|---|---|
| 영업 인허가 | 영업신고·허가·등록, 상호·대표자·소재지 변경신고, 지위승계, 폐업 |
| 토지·건축·농지 | 건축신고·허가, 용도변경, 가설건축물, 개발행위허가, 농지·산지 전용, 농지취득자격증명, 토지보상 |
| 행정처분 대응 | 사전통지 의견제출, 청문, 이의신청, 행정심판과 집행정지, 과태료 이의, 정보공개청구, 고충민원 |
| 법인·단체 설립 | 비영리 사단법인, 재단법인, 협동조합, 사회적협동조합, 비영리민간단체, 공익법인 지정(기부금영수증), 정관 변경, 해산 |
| 출입국·체류 | 외국인등록, 체류기간 연장, 체류자격 변경, 초청, 외국인 고용 |
| 문서 작성 | 내용증명, 통지서, 합의서·확인서, 위임장, 진정서·탄원서, 질의서 |
| 농축산 인허가·인증 | 축산업 허가·등록, 가축분뇨 배출시설, 농업경영체 등록, 해썹 인증, 유기축산 인증 |
| 국공유재산 | 국유재산·공유재산 사용허가와 대부, 국유림 대부, 초지, 갱신, 원상회복, 변상금 |
| 단체 운영·지원사업 | 총회·이사회, 주무관청 보고, 입법예고 의견, 법령 해석 요청, 정책 건의, 보조금 신청·정산 |

**법원·등기소에 내는 일** (법무사가 하던 일)

| 영역 | 업무 |
|---|---|
| 법인 등기 | 회사 설립, 임원·본점·상호·목적 변경, 증자, 지점, 해산·청산, 농업법인·민법 법인 등기 |
| 부동산 등기 | 매매·증여·상속 소유권이전, 근저당·전세권 설정과 말소, 주소·이름 변경 |
| 민사 소송 서류 | 지급명령, 소액사건, 소장, 답변서, 준비서면, 조정, 판결 뒤 절차 |
| 보전·집행·공탁 | 가압류, 가처분, 채권압류·추심, 재산명시, 강제경매, 공탁 |
| 가사·비송 | 상속포기·한정승인, 개명, 가족관계등록 정정, 후견, 협의이혼, 유언 |
| 회생·파산 | 개인회생, 개인파산·면책 |

표에 없는 업무도 같은 순서로 근거 법령부터 찾아 처리합니다. 관청과 공문이 여러 번 오가는 일(대부 갱신, 원상회복 요구, 처분 불복)과 법인·단체의 일은 사건 하나로 묶어서, 받은 공문과 기한, 낸 서면과 접수증을 끝날 때까지 관리합니다.

## 어떻게 일하나

어떤 일이든 같은 순서로 합니다.

1. 사정을 듣고 해야 하는 신청을 빠짐없이 찾습니다. 사정 하나에 신청이 여럿 걸리는 것이 보통입니다.
2. 현행 법령에서 근거, 관할, 서식, 기한을 찾습니다. 기억나는 대로 쓰지 않고 조문을 읽습니다.
3. 먼저 거쳐야 하는 절차가 있는지 봅니다. 등기 전에 관청에서 신고확인증이나 허가서를 받아 와야 하는 경우가 있어서입니다.
4. 서류 초안을 쓰되, 모르는 사실은 지어내지 않고 빈칸으로 남긴 뒤 묻습니다.
5. 접수 담당자, 담당 주무관, 등기관, 재판부가 물을 질문을 미리 뽑아 답과 증빙을 채웁니다. 보완 요구가 나오기 전에 막으려는 것입니다.
6. 내기 전에 다른 에이전트 둘이 따로 검토합니다.
7. 제출용으로 만듭니다. 첨부는 A4 PDF로 만들고, 국민신문고에 붙여 넣을 글과 신청인이 할 일 목록을 함께 냅니다.
8. 내고 나서는 접수번호, 기한, 보완·보정 기록, 뒤따르는 신고를 적어 둡니다.

| 에이전트 | 일 |
|---|---|
| 바룩 (baruch) | 쓰는 역할입니다. 사정을 듣고 순서를 정해 서류를 씁니다 |
| 사반 (shaphan) | 대조하는 역할로, 서류를 조문, 사실, 다른 서류와 한 글자씩 맞춰 봅니다. 직접 고치지는 않고 판정만 냅니다 |
| 나단 (nathan) | 받는 쪽 역할을 맡아 담당 공무원, 등기관, 재판부, 상대방의 자리에서 읽고 약한 곳을 짚습니다. 나단도 고치지 않습니다 |

## 하지 않는 일

- **대신 신청하지 않습니다.** 서명, 날인, 본인 인증, 제출은 신청인이 합니다.
- **법정에 나가 변론하지 않습니다.** 상대가 다투는 복잡한 소송, 금액이 크고 되돌릴 수 없는 일(대금과 맞바꾸는 부동산 등기, 큰 금액의 가압류), 불변기간이 며칠 남지 않은 일은 전문가에게 맡기라고 말합니다. 그때는 만든 서류 묶음을 그대로 넘기면 됩니다.
- **허가·등기·승소를 보장하지 않습니다.** 판단은 관청, 등기소, 법원이 합니다.
- 형사 사건, 세무 조정, 노무 분쟁, 특허는 다루지 않습니다.
- **법률 자문이 아닙니다.** 업무 카드는 작성일의 조문을 읽고 쓴 참고 자료이며, 일할 때마다 현행 조문으로 다시 확인합니다. 해석이 갈리는 곳은 `[전문가 확인]`, 관청에 물어야 하는 것은 `[관청 확인]`으로 표시합니다.
- 돈을 받고 남의 서류를 만들어 주는 일에는 행정사·법무사·변호사 자격이 필요합니다. 바룩은 자기 일을 직접 하는 사람이 쓰는 도구입니다.

## Claude나 ChatGPT에 연결해 쓰기

Claude Code를 쓰지 않아도 됩니다. 쓰고 계신 AI에 아래 주소를 커넥터로 등록하면 대화창에서 바로 씁니다.

```
https://baruch-ebon.vercel.app/mcp
```

| 어디서 | 등록하는 곳 |
|---|---|
| Claude (웹, 데스크톱 앱) | 설정의 커넥터에서 "커스텀 커넥터 추가"를 누르고 주소를 붙여 넣습니다. 이름은 "바룩"으로 적으면 됩니다. |
| ChatGPT | 설정의 커넥터(앱)에서 개발자 모드를 켜고 커스텀 커넥터를 만들어 주소를 붙여 넣습니다. 인증은 "없음"으로 둡니다. |

등록한 뒤에는 "바룩으로 대표이사 주소 변경등기를 도와줘"처럼 말하면 됩니다. 요금제에 따라 커넥터를 쓸 수 있는 범위가 다르고 메뉴 이름도 자주 바뀌니, 안 보이면 각 서비스의 도움말에서 "커스텀 커넥터"를 찾아보십시오.

대화창에서 쓸 때는 Claude Code와 다른 점이 있습니다.

- 서류를 폴더에 파일로 쌓지 않고 대화 안에서 한 건씩 써 줍니다. 파일 만들기 기능이 있는 AI라면 문서나 PDF로 받을 수 있습니다.
- 검토를 맡을 에이전트가 따로 없어서, 같은 AI가 대조하는 역할과 받는 쪽 역할을 차례로 맡아 스스로 검토합니다.
- 연결 서버는 업무 안내와 법령 조문만 돌려줍니다. 이름이나 주소, 사연은 서버로 보내지 않게 되어 있고, 대화 내용은 쓰고 계신 AI 서비스의 약관을 따릅니다.

## 설치

Claude Code에 두 줄을 입력해 설치합니다.

```
/plugin marketplace add moomoogrange/baruch
/plugin install baruch@baruch
```

파이썬 3과 git이 필요하고, PDF를 만들려면 크롬이나 엣지도 깔려 있어야 합니다. 법령 저장소(약 65MB)는 처음 쓸 때 `~/.local/share/baruch/law-go-kr-obsidian`에 내려받습니다. 이미 받아 둔 사본이 있으면 `BARUCH_LAW_DIR` 환경변수로 그 폴더를 가리키면 됩니다.

## 쓰는 법

서류를 둘 빈 폴더에서 Claude Code를 열고 말로 합니다. "식당을 인수했는데 뭘 신고해야 하나요", "못 받은 돈이 있는데 지급명령을 내고 싶어요", "대표이사가 바뀌어서 등기해야 해요"처럼 쓰면 됩니다.

| 명령어 | 하는 일 |
|---|---|
| `/baruch:work 식당을 인수했어요` | 무슨 일이든 여기서 시작합니다. 해야 하는 신청과 순서, 근거 법령, 관할, 낼 서류, 기한을 찾습니다 |
| `/baruch:case 공문 받았어요` | 공문이 오가는 일을 사건으로 관리합니다. 받은 공문을 등록하고 기한 장부(불복 마감), 적용 법령, 서면, 접수증을 사건별로 모아 둡니다 |
| `/baruch:precheck` | 담당자가 물을 질문에 미리 답과 증빙을 채우는 사전 보완 점검입니다 |
| `/baruch:check` | 사반과 나단의 상호 검토 |
| `/baruch:pdf` | 제출용 PDF 만들기 |
| `/baruch:registry-check 대표이사 변경등기` | 등기 신청 사전 점검입니다. 등기 전에 받을 서류를 찾고 신청서를 칸별로 대조합니다 |
| `/baruch:status` | 진행 상황, 기한, 접수번호와 회신 기록 |
| `/baruch:law 민법 32` | 법령 조회 |

만든 파일은 `업무/<업무 이름>/` 아래에 쌓입니다.

## 기부금영수증을 원한다면 먼저 알 것

1. 법인을 세웠다고 바로 기부금영수증을 줄 수 있지는 않습니다. 설립 뒤에 국세청장의 추천을 받아 재정경제부장관의 **지정**을 받아야 합니다. 지정은 분기마다 합니다.
2. 지정 요건에 맞는 문구(공익 사용, 잔여재산 귀속, 기부금 공개)가 **정관에 있어야** 합니다. 설립할 때 넣어 두는 것이 좋습니다.
3. 사업의 직접 수혜자가 **불특정 다수**여야 합니다. 회원이나 참가비를 낸 사람만 혜택을 보는 구조면 이 요건이 쟁점이 됩니다.
4. 프로그램 **참가비는 기부금이 아닙니다.** 대가로 받은 돈에는 기부금영수증을 줄 수 없습니다.

## 법령은 어디서 읽나

법령을 읽는 방법은 두 가지입니다. 서류에 적는 조문은 항상 현행 조회로 확인합니다.

| | 현행 조회 | 내려받은 저장소 |
|---|---|---|
| 출처 | 류주임이 만든 [korean-law-mcp](https://github.com/chrisryugj/korean-law-mcp) 공개 서버 (법제처 Open API) | 직접 만든 법령 저장소 [law-go-kr-obsidian](https://github.com/moomoogrange/law-go-kr-obsidian)의 사본 |

- 플러그인을 설치하면 현행 조회 서버가 함께 연결되고, 인증키 없이 공용 한도로 동작합니다. 설치할 때 묻는 "법제처 Open API 인증키"는 비워 둬도 됩니다. 자주 쓴다면 [open.law.go.kr](https://open.law.go.kr)에서 무료로 받아 넣으면 본인 한도로 조회합니다.
- 현행 조회는 공개 서버(mcp.gomdori.app)를 거쳐 법제처로 갑니다. 법령 이름과 조 번호만 보내고, 신청인의 개인정보는 보내지 않습니다. 이 서버를 쓰고 싶지 않으면 플러그인의 MCP 연결을 끄면 되고, 그때는 내려받은 저장소만으로 동작합니다.
- 관청 내부 기준, 표준정관, 처리 관행은 어디에도 없습니다. 관청에 물어야 합니다.
- 절차 안내의 일부는 법제처 찾기 쉬운 생활법령정보(https://www.easylaw.go.kr) 「비영리 사단법인」(2026년 10월 15일 기준)을 간추린 것입니다. 이 자료는 유권해석이 아닙니다.

## 구성

```
.claude-plugin/     플러그인·마켓플레이스 정의
agents/             baruch, shaphan, nathan
commands/           work, case, precheck, check, pdf, registry-check, status, law,
                    start, sinmungo-ask, docs, sinmungo-apply, registry, tax (비영리 사단법인)
mcp/                Claude·ChatGPT 연결 서버 (api/mcp.js, 대화창용 규칙, 배포 스크립트)
docs/               소개 쪽
skills/
  work-engine/              어떤 업무든 따르는 공통 절차, 업무 카드 형식
  admin-affairs/            관청에 내는 일의 업무 카드 (references/ 6개 영역)
  judicial-affairs/         법원·등기소에 내는 일의 업무 카드 (references/ 6개 영역)
  case-file/                공문이 오가는 일을 사건으로 관리 (기한 장부, 증거 보관, 단체의 일)
  law-lookup/               법령 조회 (scripts/law.py)
  nonprofit-incorporation/  비영리 사단법인 설립 (references/, templates/)
  registry-check/           등기 신청 사전 점검 (선행 신고·허가, 신청서 대조)
  cross-check/              상호 검토 절차
```

업무 카드는 `skills/work-engine/references/카드-형식.md`의 형식에 맞춰 누구나 더할 수 있습니다. 카드에는 현행 조문을 읽고 확인한 것만 적고, 확인하지 못한 것은 표시로 남깁니다.
